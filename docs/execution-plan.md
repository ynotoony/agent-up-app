**依据**：用户于 2026-09-15 要求补齐执行计划。提出后被告知确认 §7 或改数字，用户回复「继续」。按可追溯明确指令，将 §4–§7 默认建议收为已批准假设。`development-plan.md` 仍待确认，不以第 28 节阻挡 W0。

## 0. 怎么用

- 只做首版垂直切片，不做平台。
- 每一波必须有：**用户能看见的演示**、**退出测试**、**明确不做**。过不了退出测试不准拆下一波的票。
- M1 及以后的票名是预告，**现在不创建文件**。M0-03 未 `done` 之前拆 M1，就是把未闭合的安全边界交给写代码的人。
- 预算和场景脚本是**默认建议**。你改数字或改场景，改这里，不要在实现里偷偷放宽。

## 1. 首版终点（W7 才算产品）

用户在本机（macOS 或 Windows）安装后可以：

1. 添加一个项目根目录，未确认前零写入。
2. 用一句话提需求，在讨论里补文字和图片。
3. 看到当前理解、方案和任务范围，并在关键取舍上做决定。
4. 跑通 Implement → 独立 Review → Commit（Review 失败不能 Commit）。
5. 打开结果、反馈、开下一轮、接受结果。
6. 关掉 App 后从 `.agentup/` 恢复，不依赖 SQLite 或内存。

首版明确不做：账号/团队/远程同步、移动端、邮件、多根目录、跨项目写入、关闭后继续跑 Agent、静默自动更新、插件市场、从 `properties/react` 迁代码或 demo 数据。

## 2. 波次（从现在到发布）

复杂度：W0/W2 起涉及路径与权限，按 C3 派 Implementation，Coordinator 不得降级手写。

### W0 — 能打开并恢复（当前）

- **票**：`docs/issues/03-m0-runtime.md`（ready）。不另拆 M0-04。
- **演示**：打开 App → 选目录 → 扫描 → 预览不写盘 → 确认初始化 → 创建 `draft` 需求 → 杀进程再开 → 项目和需求仍在。
- **退出**：`SPEC-002` 五条 command 可用；renderer 无 fs/shell/process/network/secret；五类威胁有外部行为测试；fingerprint 只用 `fp-v1`；错误形状为 `{ok, command, error}`。
- **不做**：讨论、附件、Agent、SQLite 事实源、项目删除、多项目切换器可以极简，但不能扩大 command 集。
- **下一波门**：本票 `done`。

### W1 — 事实层可脱离 UI 存活（M1）

- **预告票**：M1-01 其余用户事实类型的 type-specific schema 与 writer/reader；M1-02 SQLite 仅作投影，删除后仍能从 `.agentup/` 重建。
- **先决**：W0 done；新建规格（不得把未定义的 discussion/plan/task content 直接写进代码）。
- **演示**：无 App UI，用 fixture 写入多类事实和事件；重启进程读回；删 SQLite 再重建，索引一致。
- **退出**：revision CAS、事件幂等、原子写入失败保留旧版；SQLite 损坏不阻断 load。
- **不做**：Agent、附件二进制大文件策略可先定上限但只测小 fixture。

### W2 — 项目作为产品对象（M2）

- **预告票**：M2-01 项目列表/失效目录/重新绑定；M2-02 删除项目时备份或清空 `.agentup/` 且不影响项目源码。
- **演示**：两个项目互相隔离；拔掉目录后有可读错误和下一步；删除只动 `.agentup/`。
- **退出**：初始化前零写入仍成立；跨根目录写入测试失败。
- **W2.5 外部变化门**（不过门不准进 W3）：外部改文件、Git 未提交、符号链接、并发写入、目录失效，均不能静默丢用户改动。

### W3 — 讨论可恢复（M3）

- **预告票**：M3-01 文字讨论事实；M3-02 图片附件落盘与预览（受预算上限约束）。
- **演示**：文字 + 多图评论关掉 App 还在；附件不存在浏览器内存里。
- **退出**：超大附件拒绝并说明；三种场景都能完成「用户发言被记录」，此时还不要求 Agent 回复。

### W4 — 范围和任务可见（M4）

- **预告票**：M4-01 范围版本与差异；M4-02 任务拆分与同构子任务。
- **先决**：W3；需要单独批准的范围/任务规格（当前只有生命周期名，没有 content schema）。
- **演示**：用户能看见「涉及哪些文件、为什么、相对上一版改了什么」。
- **退出**：范围变化有事件；用户不能直接写状态字段。

### W5 — Agent 真跑（M5）

- **预告票**：M5-01 本地可替换 provider（先假 provider/录制回放，再接真模型）；M5-02 Implement；M5-03 独立 Review；M5-04 受限工具（读、范围内写、受限命令）。
- **先决**：W4；**M0-C 门**（上下文优先级、prompt 版本、成本上限、重试、injection 防护）必须先有 approved 规格。没有 M0-C 就接真模型，等于把密钥和项目源码交给未定义的 agent。
- **演示**：普通任务 Implement → Review → 可提交；高风险任务换独立 Review 身份；Review fail 不能 Commit。
- **W5.5 运行可靠性门**：取消、超时、重试、休眠、崩溃、子进程清理。不过门不准进 W6。

### W6 — 结果和下一轮（M6）

- **预告票**：M6-01 不可变结果版本；M6-02 反馈开新一轮；M6-03 历史比较且不污染当前目标。
- **演示**：接受/拒绝有记录；反馈图文进入讨论并生成新任务。

### W7 — 三场景产品化（M7）

- **预告票**：M7-01 三场景 E2E；M7-02 打包（macOS/Windows）、手动更新说明、诊断包、隐私说明。
- **退出**：§4 三条场景脚本全绿；1440/1024/768 无横向溢出；键盘走通主路径；去掉 `properties/` 仍能构建。
- **W7.5 发布门**：安装、升级失败回滚、事实备份恢复、诊断包脱敏、安全测试。不过门不准宣称发布。

## 3. 场景验收脚本（草案）

共同前置：本机已安装对应当前波次的 App；测试项目是临时目录，不含生产密钥；网络在 W5 之前默认断开。

公共失败断言：未确认不写盘；错误不回显根外路径；杀进程后从 `.agentup/` 恢复。

### S1 界面改造

1. 打开一个含若干前端文件的临时项目，完成初始化。
2. 需求：「把主按钮改成主色，并保证键盘可聚焦」。
3. 讨论中补一张截图和一句约束（「不要改路由」）。
4. 出现方案和范围；用户确认只改指定文件。
5. Implement → Review 故意失败一次 → 修正 → Review 通过 → 形成结果。
6. 用户反馈「对比度不够」+ 图 → 新一轮 → 接受。
- **W0 可测片段**：步骤 1 和杀进程恢复。W3 起测步骤 3。W5 起测步骤 5。W6 测步骤 6。W7 全绿。

### S2 Bug 修复

1. 初始化一个能复现「点击保存无反应」的最小项目。
2. 需求写复现步骤；讨论贴错误截图。
3. 范围指向可疑文件；用户批准最小范围。
4. Implement 改代码；Review 检查未越权改无关文件。
5. 结果页可打开改动说明；接受后历史可对比。
- **W0 可测片段**：初始化与 draft 需求。W4 测范围。W5 测越权失败。W7 全绿。

### S3 模糊想法评估

1. 需求只有「这个目录值不值得做成产品」，无明确文件范围。
2. Agent 必须先提问或给出待决定项，不能直接改文件。
3. 用户补充目标用户和「本周只评估不写代码」。
4. 产出评估结果版本（文档/说明），无源码写入。
5. 用户接受评估或拒绝并开新需求。
- **W0 可测片段**：draft 需求保存。W5 测「无范围则禁止写源码」。W6 测结果版本。W7 全绿。

另测（从 W0 开始累加，W7 必须全有）：无项目、路径失效、权限拒绝、重复提交、旧 revision、符号链接穿越、刷新恢复、窄屏。

## 4. 资源预算（默认建议，proposed）

超过上限必须提示或降级，禁止卡死、崩溃、静默丢数据。

| 项 | 默认上限 | 超限行为 |
| --- | --- | --- |
| 扫描文件数 | 50_000 | 停止扫描，报告已扫数量和跳过原因 |
| 单文件读入 renderer | 1 MiB | 只返回元数据；需要时分页/显式打开 |
| 附件单文件 | 10 MiB | `invalid_input`，不落盘 |
| 单需求附件总大小 | 100 MiB | 拒绝新增 |
| 单需求评论数 | 500 | 分页；禁止一次性拉全量 |
| 首次扫描（1 万文件） | 目标 ≤ 5s，硬超时 30s | 部分结果 + 超时错误 |
| SQLite 重建（1 万事实） | 目标 ≤ 10s | 显示进度；失败不破坏 `.agentup/` |
| 讨论/历史列表 | 50 条窗口 | 虚拟化或分页 |
| Agent 上下文 | 默认 32k token，硬顶 128k | 截断并记录被丢弃的来源 |
| 单任务 run | 15 min | 取消并留事件 |
| 并发 Agent | 1 个 Implement + 1 个 Review | 拒绝第三路 |
| App 内存 | 警告 1.5 GiB / 失败 2 GiB | 停 run、保留事实 |
| `.agentup/` 体积 | 警告 2 GiB | 禁止新附件，提示导出/清理 |
| UI 首屏 | 2 s | 未达标记诊断，不假绿 |
| 只读 command p95（已绑定项目、≤1000 文件元数据） | 100 ms | 记诊断 |

成本：首版不接计费 API。接真模型前必须在 M0-C 规格里写单任务费用上限和用户可见的花费。

## 5. 发布（默认建议，proposed）

- 渠道：手动分发 macOS / Windows 安装包；Linux 不进首版。
- 更新：手动下载；**不做静默自动更新**。
- 数据：安装 ≠ 事实；卸载 App 不删除各项目 `.agentup/`。提供「导出全部事实」和「恢复检查」。
- 兼容：`.agentup` `format_version` 只增不改语义；升级失败回滚到旧 App 仍能读旧事实。
- 诊断：用户导出脱敏包（无文件正文、无绝对路径、无密钥）。默认不上送。
- 签名：发布门必须有签名方案；未签名不得称稳定版。
